# Kali-Security-MCP 能力升级总计划

> 版本：2026-07-25（P0/M2 主链路已在 Kali 真机验收；Phase2 余项 Observer / propose_insights / ATT&CK coverage 已接线；Phase3 报告 Markdown 导出已落地 `report_export.py` / `export_task_summary`；单测见 `tests/test_p0_harness.py`；见 `doc/runbook-internal.md`）  
> 适用对象：公安内部 AI 自主合规渗透测试系统（基于当前 Kali MCP 原型）  
> 授权口径（产品侧）：内部使用；不强制 engagement 闸门；轻量操作记录（what/when）；报告保留真实复现数据、默认不脱敏  
> 范围：能力提升优先，不以合规拦截、不以工具数量刷榜为目标  

---

## 1. 问题定性

当前原型是**可执行的工具桥**，还不是**会续打的渗透智能体**。

| 已有 | 缺的 |
|------|------|
| MCP 入口、`LocalCommandExecutor`、大量 `mcp_tools` 注册 | 共享工作记忆（目标图/黑板） |
| 部分 output_parsers、agent 架子、决策/自主引擎模块 | 阶段剧本驱动、证据门、跨轮续跑 |
| tool profile / engagement 相关代码 | 主脑工具面收敛；「灵光」不得直接驱动执行，只能产候选假设 |
| 会话与全局 dict 状态 | 结构化 Finding + 可重放证据链 |

公安侧“笨”的体感，与 TCH/开源强队复盘中的同类失败一致：**扫完不会接、记不住、验不实、上下文一爆就重来**。

## 2. 产品目标与非目标

### 2.1 目标（可验收）

1. **全自动闭环**：给定任务目标列表，系统按阶段推进至报告，无需逐步点工具。  
2. **会续打**：中断/上下文压缩后，从 handoff 与图状态继续，不从零全量重扫。  
3. **可举证**：每条对外 finding 至少达到 `verified`，附可重放命令与完整回显/样本路径（真值，默认不脱敏）。  
4. **可复盘**：JSONL 记录何时、对谁、调了什么、证据落在哪（轻量，不挡执行）。  
5. **ATT&CK 可汇报**：阶段与 finding 可挂 tactic/technique 标签，支撑覆盖看板与报告章节（标签层，非主运行时）。

### 2.2 非目标（本阶段明确不做）

- 强制 engagement / 范围硬拦截作为默认启动条件  
- 报告默认脱敏、审批流、不可抵赖审计链  
- 为填 MITRE 矩阵遍历全部 Technique  
- 再堆 APT/PWN/C2/WebShell 运营台门面  
- 整库迁 Go/换框架（CyberStrike 可借鉴，不整仓搬）

## 4. 目标架构

### 4.1 分层

```
┌─────────────────────────────────────────────────────────┐
│  编排层 Orchestrator（主模型可见工具面极瘦）              │
│  start_task / run_playbook / graph_* / verify / log /   │
│  export_report / continue_from_handoff                  │
├─────────────────────────────────────────────────────────┤
│  状态层 Blackboard / Target Graph + Task State Machine  │
│  节点: host/port/service/url/tech/account/finding       │
│  边: exposes/runs/same_origin/evidence_of/...           │
│  阶段: RECON→FINGERPRINT→VERIFY→EXPAND→EVIDENCE→REPORT  │
├─────────────────────────────────────────────────────────┤
│  技能层 Skills / Playbooks（按阶段渐进加载）              │
│  web_surface / api_surface / auth_surface / svc_surface │
├─────────────────────────────────────────────────────────┤
│  执行层 Solver（子执行器 / 可选子 Agent）                 │
│  YAML 配方 → LocalCommandExecutor → 白名单二进制        │
├─────────────────────────────────────────────────────────┤
│  证据与记录层                                           │
│  EvidenceStore（原样） + action_log JSONL + Finding DB  │
│  Observer（旁路：重复扫/死路/超时熔断建议，不拦启动）      │
└─────────────────────────────────────────────────────────┘
```

### 4.2 数据主对象

**Task**

- `task_id`, `targets[]`, `depth`, `policy_flags`（如是否允许横向/数据外带类动作）  
- `phase`, `status`, `created_at`, `updated_at`

**GraphNode / GraphEdge**

- `id`, `type`, `value`, `confidence`, `last_seen`, `evidence_paths[]`, `next_checks[]`, `dead_reason?`

**Finding**

- `finding_id`, `title`, `severity`, `status` ∈ {candidate, verified, false_positive, blocked}  
- `reproduce_cmd`, `expected_signal`, `evidence_paths[]`  
- `tactic?`, `technique_ids[]`（ATT&CK 可选）  
- `raw_notes`（真值，不脱敏）

**ActionLog（JSONL 一行）**

- `ts`, `task_id`, `phase`, `target`, `tool`, `args_digest`, `exit`, `duration_ms`, `evidence_path`, `finding_ids`

**Handoff**

- `compact_handoff.md` / 结构化 JSON：已做、已否、死路、下一步、图快照指针

### 4.3 主循环（全自动）

```
load_or_create_task
→ ensure_graph
→ while not terminal:
    next = graph_next_actions(task)  # 或当前 phase 的 playbook 队列
    if empty: advance_phase or stop_reason
    run_playbook_or_tool(next)
    parse → upsert_graph
    for candidates: verify_finding
    write action_log + evidence
    if budget/熔断: break
→ export_report(verified only 或 candidate 分区标注)
→ close_task
```

### 4.3.1 「灵光 / 自主洞察」如何结合（保留能力、改接线）

目标：不扔掉 `autonomous_engine` 一类模块的跨域联想能力，但**禁止它当方向盘**。

```
主路径（默认、高优先级）
  graph_next_actions / playbook 队列
       ↓
  Solver 执行 → parse → graph → verify → evidence

支路（可选、限预算）
  InsightEngine.propose(graph_snapshot, phase, recent_failures)
       ↓
  产出 Hypothesis[]（不是直接 tool call）
       ↓
  过滤器（必须全部满足才进入候选队列）:
    1) 绑定已有 GraphNode（有 target/url/service，禁止悬空脑洞）
    2) 给出 reproduce_cmd 草案 + expected_signal
    3) 与已失败假设 / dead 节点去重
    4) 本 phase 洞察预算未用尽（如每阶段最多 K 条）
       ↓
  写入 finding.status = candidate（来源 source=insight）
       ↓
  与其它 candidate 一样走 verify_finding
       ↓
  verified → 进报告主表；失败 → false_positive / blocked，回写图 dead_reason
```

| 规则 | 说明 |
|------|------|
| 默认开关 | `insight.enabled=true` 可开模块，但 `insight.drive_executor=false`：不得跳过 playbook 直接调 Kali |
| 触发时机 | 优先：当前 phase 的 next_actions 空、或连续 N 次验证失败、或 playbook 结束仍无 verified；**不要**每轮强制抽卡 |
| 随机性 | 若实现含 random，仅用于**假设排序扰动**，且排在规则分（可行性、与图相关性）之后；主路径调度本身不 random |
| 与 ATT&CK | 洞察产出可猜 `technique_ids[]`，不确定则空；标签错误不如不标 |
| 与 MCP | 对外可只暴露 `propose_insights(task_id)` / 或并入 `graph_next_actions(include_insights=true)`；主脑仍不直接面对 200 工具 |
| 日志 | action_log 记 `source=insight`，复盘能区分剧本命中 vs 灵光命中 |
| 报告 | 默认仅 verified；洞察未验证条目可进附录「未证实假设」，不与实锤混排 |

**结合后的决策优先级（固定）：**

1. 图上明确的 `next_checks` / playbook 步骤  
2. 已有 candidate 的 verify 队列  
3. 预算内、已绑定节点的 insight hypotheses  
4. 阶段推进或 stop_reason  

这样既保留「灵光」探索面，又与全自动、真值证据、MCP 瘦面同一套闸门。

### 4.4 ATT&CK 嵌入方式

- **运行时**：阶段枚举与 playbook 元数据挂默认 tactic 列表。  
- **结果时**：verified finding 尽量填 `technique_ids`；不确定则空。  
- **验收时**：覆盖矩阵 = 本任务出现过的 technique 集合 + 未覆盖说明。  
- **禁止**：为填格强制执行无关 T 编号。

建议阶段粗映射（可调）：

| 内部阶段 | ATT&CK Tactic（示例） |
|----------|------------------------|
| RECON | Reconnaissance |
| FINGERPRINT | Discovery / Collection（视动作） |
| VERIFY | Initial Access / Execution（验证级） |
| EXPAND | Privilege Escalation / Lateral Movement（策略开关） |
| EVIDENCE | Collection |
| REPORT | —（文档） |

## 6. 分阶段实施计划

### Phase 0 — 基线冻结（0.5～1 天）

**目的**：可回滚、可对比“变聪明前后”。

- [ ] 记录当前启动方式、`status_check` 结果、一轮手动 nmap/httpx 样例输出  
- [ ] 明确任务目录约定：`workspace/tasks/{task_id}/{graph,evidence,logs,report}/`  
- [ ] 冻结本计划非目标，避免并行堆新工具模块  

**出口**：任务目录约定写入 `doc/runbook-internal.md` 草稿。

---

### Phase 1 — P0 能力五件套（约 7～10 天）

#### 1.1 Target Graph（2～3 天）

- 实现内存图 + JSON 落盘  
- API：`graph_upsert`, `graph_query`, `graph_next_actions`, `graph_mark_dead`  
- 单测：合并去重、死节点不再推荐  

#### 1.2 解析进图（2 天）

- 打通 executor → parser → graph  
- 优先：nmap、httpx、whatweb/指纹、nuclei 摘要、ffuf/ferox 路径  
- 原始 stdout 进 `evidence/`，模型侧只回摘要  

#### 1.3 Playbook `web_surface`（2 天）

序列（可配置 depth）：

1. 存活/HTTP 探测  
2. 技术栈指纹  
3. 浅目录/关键路径  
4. nuclei 标签子集（非全量乱打）  
5. 产出 candidate findings  

#### 1.4 Verifier + Evidence（1～2 天）

- `verify_finding`：重放最小命令、匹配信号、写 evidence、升格/降级  
- 真值保留：完整回显与样本不脱敏  

#### 1.5 Action Log（0.5～1 天）

- JSONL：ts/task/phase/target/tool/args/duration/evidence/finding_ids  
- 不拦截执行  

**Phase 1 验收**

- 内网/本地靶场一个 HTTP 目标  
- 一键或单工具 `start_task`+`run_playbook web_surface`  
- 产出：非空 graph、≥1 条 **verified** finding（靶有洞时）或明确 false_positive/blocked 记录  
- `actions.jsonl` 可按时间回放  

---

### Phase 2 — 少笨、能续跑（约 5～7 天）

#### 2.1 状态机固化

- 阶段枚举与转移条件、每阶段停止条件（无新节点 N 步、错误率、超时）  
- 跨阶段串行，同阶段有限并行  

#### 2.2 Handoff / Progress

- 任务内 `progress` 摘要；压缩或重启时 `continue_from_handoff`  
- 禁止把无限笔记回灌主上下文  

#### 2.3 主脑工具面收敛

- 默认注册瘦 API；raw Kali 工具仅子执行器/显式 debug profile  
- 对齐 CHYing「可见性」思想（实现可用 profile + 注册表，不魔改上游 CLI）  

#### 2.4 Observer 旁路

- 检测：同 target+tool+args 重复、全 403/WAF、空结果循环  
- 输出熔断建议写入日志/图 `dead_reason`，默认自动降速/跳过，**不做人审弹窗**  

#### 2.5 洞察支路接线（结合 autonomous_engine）

- 将 `autonomous_engine` 改为 `Hypothesis` 生成器接口：输入图快照+阶段+失败史，输出结构化假设  
- 去掉（或降级）「洞察直接选 tool 执行」；统一进 candidate → verify  
- 配置：`insight.enabled`、`insight.max_per_phase`、`insight.only_when_stuck`  
- 单测：悬空假设被拒；未 verify 不得出现在报告主表  

#### 2.6 ATT&CK 字段

- playbook 元数据 + finding.technique_ids  
- 报告可按 tactic 分组（可选）  

**Phase 2 验收**

- 人为中断后 `continue` 不从零全量探测  
- 重复调用命中跳过或缓存  
- finding 带 technique 标签比例可统计（不要求 100%）  

---

### Phase 3 — 剧本扩展与报告（约 5～7 天）

#### 3.1 新增 Playbook

- `api_surface`：openapi/路由/无鉴权探测  
- `auth_surface`：登录与逻辑类验证清单（可控强度）  
- `svc_surface`：非 Web 端口指纹 + 已知问题验证级检查  

#### 3.2 Skills 目录

- `skills/` 或 `playbooks/docs/`：阶段说明按需加载，减上下文  

#### 3.3 报告导出

- verified 列表 + 时间线（来自 action_log）+ 证据路径  
- docx/markdown 模板；**真值复现材料**  
- ATT&CK 覆盖附录  

#### 3.4 YAML 工具配方试点

- 10～20 个高频工具配方替换裸拼命令  

**Phase 3 验收**

- 多类型目标任务可自动选 playbook  
- 一键导出报告，含证据与执行时间线  

---

### Phase 4 — 硬化与多目标（约 5 天，可并行部分）

- 多目标队列、并发上限、超时与资源配额  
- 结果缓存 TTL  
- 契约测试 + 靶场 e2e 固定集  
- `status_check` 展示：图规模、阶段、verified 数、日志路径  
- 性能结论**仅在实测后**写入，本计划不预设耗时指标

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 继续堆工具不改主路径 | P0 完成前禁止新增 mcp_tools 门面模块 |
| 模型仍直接点 raw 工具 | 默认瘦注册 + 文档/系统提示只暴露编排 API |

| 全自动误伤生产 | 任务级 policy_flags；高危 playbook 默认关（内部策略，非 engagement 表单） |
| ATT&CK 填错 | 允许空；错误标签不如不标 |
| 范围蔓延成 CyberStrike 克隆 | 明确不搬 C2/多端机器人；只偷 harness |

## 11. 决策记录（已对齐）

| 议题 | 决定 |
|------|------|
| engagement 强制 | 不做默认强制 |
| 审计 | 轻量 what/when 记录，不挡执行 |
| 报告脱敏 | 默认不脱敏，真值复现 |
| 能力 vs 合规闸门 | 先能力（图/剧本/验证/续跑） |
| MITRE ATT&CK | 标签与覆盖尺，不整库按矩阵重写 |
