内⽹渗透指南
1. 内⽹安全检查/渗透介绍
1.1 攻击思路
        有2种思路：
        攻击外⽹服务器，获取外⽹服务器的权限，接着利⽤⼊侵成功的外⽹服务器作为跳板，
攻击内⽹其他服务器，最后获得敏感数据，并将数据传递到攻击者，看情况安装⻓期后⻔，实
现⻓期控制和获得敏感数据的⽅式；
        攻击办公⽹的系统、办公⽹电脑、办公⽹⽆线等⽅式，⼀般是采⽤社⼯，实现控制办公
电脑，再⽤获得的办公⽹数据，可能是内⽹的各种登录账号和密码，再获取办公⽹或者⽣产⽹
的有⽤数据。
        ⼀般内⽹安全检查使⽤第⼀种思路，实际的攻击2种思路结合实现。
1.2 敏感资料/数据/信息
        ⾼管/系统管理员/财务/⼈事/业务⼈员的个⼈电脑
        ⽂件服务器/共享服务器
        邮件服务器
        OA服务器
       数据库服务器
1.3 攻击过程
        按照第⼀种思路，个⼈认为可以分为4个阶段：
                信息收集
                漏洞验证/漏洞攻击
                后渗透
                ⽇志清理
        第⼆种思路，社⼯的⽐重更⼤⼀些，本篇不多做介绍。
2 信息收集
        该阶段识别内⽹存活的主机 IP， 运⾏端⼝扫描和漏洞扫描获取可以利⽤的漏洞

2.3 漏洞扫描
        有授权的情况下，使⽤绿盟极光、Nessus、Nexpose 等漏扫⼯具直接扫描⽬标，可以
直接看到存活主机和主机的漏洞情况。
2.4 识别内⽹环境
        获取⽬标的主机存活信息和端⼝开放信息后，就可以尝试分析⽬标的⽹络结构，安全防
御策略。按照办公⽹和⽣产⽹分别说⼀下：
2.4.1 办公⽹
        按照系统区分：
                OA系统
                邮件系统
                财务系统
                ⽂件共享系统
                域控
                企业版杀毒系统
                上⽹⾏为管理系统
                内部应⽤监控系统
        按照⽹络区分：
                管理⽹段
                内部系统⽹段
                按照部⻔区分的⽹段
                按照设备区分：
                个⼈电脑
                内⽹服务器
                ⽹络设备
                安全设备
        办公⽹的安全防护⽔平⼀般较差（相对），能绕过杀毒软件基本上就畅通⽆阻了，利⽤
信任关系容易扩⼤攻击⾯，获取数据也⽐⽣产⽹简单。
2.4.2 ⽣产⽹
        按照系统区分：
                业务系统
                运维监控系统
                安全系统
        按照⽹络区分：
                各不同的业务⽹段
                运维监控⽹段
                安全管理⽹段
                根据⽬标开展的不同业务，对应的服务器可能存在不同的⽹段上，分析服务器上
运⾏的服务和进程可以推断⽬标使⽤的运维监控管理系统和安全防护系统，可以⼤概推断出⼊
侵⽬标的 IT 运维⽔平和安全防护⽔平，在接下来的⼊侵考虑采⽤什么样的⽅法。
3 漏洞验证/漏洞攻击

        使⽤端⼝扫描、漏洞扫描验证扫描⽬标开放的端⼝，在对应端⼝上开放的服务，运⾏该
服务的软件和版本号。
        如果只是使⽤端⼝扫描，只是发现开放的端⼝，接着使⽤ nc 可以获取端⼝上服务的 
banner 信息，获取 banner 信息后需要在漏洞库上查找对应 CVE，后⾯就是验证漏洞是否存
在。如果是使⽤漏洞扫描⼯具可以直接获取对应端⼝上的漏洞，后⾯也是验证漏洞。
        安全检查⼀般是尽可能的发现所有漏洞，对漏洞的⻛险进⾏评估和修复。⼊侵的话只关
注⾼危远程代码执⾏和敏感信息泄露漏洞等可以直接利⽤的漏洞。
        漏洞验证可以找对应的 CVE 编号的 POC、EXP，利⽤代码在 ExploitDB 、seebug上
查看或者在 github 上搜索是否有相关的漏洞验证或利⽤的⼯具。

        Docker是⼀个开放源代码软件项⽬，让应⽤程序布署在软件容器下的⼯作可以⾃动化进

        这部分对于安全检查、或授权渗透测试⼯作不是重点，通常也不考虑。
        
        在做⽇志清理前需要了解以下的内容：
                攻击和⼊侵很难完全删除痕迹，没有⽇志记录本身就是⼀种⼊侵特征；
                删除或清理⼊侵系统的本地⽇志不代表删除了痕迹，在⽹络设备、安全设备、集
中化⽇志系统上仍然留存记录；
                留存的后⻔本身会有攻击者的信息；
                使⽤的代理或跳板可能会被反向⼊侵;
                在操作前检查是否有管理员登录；
                删除上传的⼯具，使⽤磁盘覆写的功能删除；
        Windows⽇志类型
                web⽇志：IIS、Apache以及其它web⽇志
                操作⽇志：3389登录列表、最近访问⽂件、IE等浏览器访问⽇志、⽂件访问⽇志
                登陆⽇志：系统应⽤⽇志-安全⽇志等
                攻击前和状态还原，尽量保持⼀致
        Linux操作⽇志
